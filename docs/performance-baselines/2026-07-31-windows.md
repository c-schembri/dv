# Windows Reference Baseline - 2026-07-31

This is observed evidence from one uncontrolled developer machine. It is not a
cross-machine target.

## Machine

- Windows 11 `10.0.22631`, x86-64
- AMD Ryzen 9 9900X, 12 cores, 24 hardware threads
- .NET SDK `10.0.100`
- release `dv` binary size: 182,784 bytes
- repository state: initial uncommitted foundation, so no commit identifier
- power plan, background load, CPU frequency, and OS page-cache state were not
  controlled

## Startup

Thirty retained samples after three warm-ups:

| Tool | Case | Min | Median | p95 | Max |
|---|---|---:|---:|---:|---:|
| `dotnet` | `--version` | 60.203 ms | 62.451 ms | 66.332 ms | 66.473 ms |
| `dv` | `--version` | 2.715 ms | 3.034 ms | 3.364 ms | 3.651 ms |

This proves only the current Phase 0 version path and process-launch cost. It
does not predict build performance.

The direct help/version classifier removed avoidable owned argument collection
from this path. A preceding 30-sample run measured a `2.988 ms` median; the
final run measured `3.034 ms`. That difference is noise at this sample size, so
no performance improvement is claimed. The structural allocation removal is
retained because the work is unnecessary and the path is simpler to cost.

## SDK Selection

Thirty retained samples after three warm-ups. The harness first verified that
both commands selected `10.0.100`:

| Tool | Command | Min | Median | p95 | Max |
|---|---|---:|---:|---:|---:|
| `dotnet` | `dotnet --version` | 61.036 ms | 63.050 ms | 66.537 ms | 66.760 ms |
| `dv` | `dv sdk current` | 3.086 ms | 3.451 ms | 4.300 ms | 4.865 ms |

The `dv` path performed native root discovery, enumerated three installed SDK
directories, parsed their versions, and selected the highest compatible SDK.

## Reference Workflows

Ten retained samples after two warm-ups using `small-console`:

| Tool | Case | Min | Median | p95 | Max |
|---|---|---:|---:|---:|---:|
| `dotnet` | cold project restore | 477.993 ms | 484.502 ms | 495.556 ms | 495.556 ms |
| `dotnet` | clean build after untimed restore | 543.458 ms | 567.595 ms | 598.390 ms | 598.390 ms |
| `dotnet` | no-op build | 448.845 ms | 467.037 ms | 511.183 ms | 511.183 ms |
| `dotnet` | warm run with no build/restore | 316.930 ms | 320.530 ms | 328.849 ms | 328.849 ms |

`restore_cold` means a fresh project copy. It does not flush OS or NuGet caches.
Fixture copying and clean-build restore were outside their named timed
intervals.

## Reproduction

```text
cargo bench-all
cargo bench-all --case cli_version --samples 30 --warmups 3 --dv target/release/dv.exe
```
